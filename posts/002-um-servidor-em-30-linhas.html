um servidor http em 30 linhas

2026-10-05 · #http #python #minimal

HTTP é texto. Um pedido é texto, uma resposta é texto, e um socket é só um cano. Vamos ver isso a funcionar sem nenhuma framework.

o código

import socket

HOST, PORT = "127.0.0.1", 8080

BODY = b"<h1>ola do socket</h1>"
RESP = (
    b"HTTP/1.1 200 OK\r\n"
    b"Content-Type: text/html; charset=utf-8\r\n"
    b"Content-Length: " + str(len(BODY)).encode() + b"\r\n"
    b"Connection: close\r\n\r\n" + BODY
)

with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
    s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    s.bind((HOST, PORT))
    s.listen()
    print(f"a ouvir em http://{HOST}:{PORT}")
    while True:
        conn, addr = s.accept()
        with conn:
            req = conn.recv(4096).decode(errors="replace")
            print(addr, req.splitlines()[0] if req else "")
            conn.sendall(RESP)

testar

python3 server.py
curl -i http://127.0.0.1:8080/

o que falta (muito)

  • routing: respondemos o mesmo a tudo
  • concorrência: um cliente de cada vez
  • validação: recv(4096) assume que o pedido cabe num pacote
  • segurança: está ligado só a localhost por uma razão
entender o que as frameworks escondem é meio caminho para as dispensares.
